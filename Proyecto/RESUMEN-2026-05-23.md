### 3. Servicio de autenticación

Se implementó `AuthService` para trabajar con el backend real:

- endpoint usado: `POST http://localhost:5075/api/empleados/login`
- request:
  - `CorreoEmpresarial`
  - `Clave`
- response:
  - `token`

Responsabilidades del servicio:

- iniciar sesión
- guardar token en `localStorage`
- devolver token actual
- validar si el usuario está autenticado
- cerrar sesión y volver a `/login`

Archivo:

- `sistema-comercial-app/src/app/services/auth.ts`

### 4. Interceptor JWT

Se implementó el interceptor para que todas las peticiones HTTP lleven:

- `Authorization: Bearer <token>`

Archivo:

- `sistema-comercial-app/src/app/interceptors/jwt.interceptor.ts`

### 5. Registro del interceptor en Angular

Se actualizó la configuración global para usar:

- `provideHttpClient(withInterceptors([jwtInterceptor]))`

Archivo:

- `sistema-comercial-app/src/app/app.config.ts`

### 6. Guard de autenticación

Se implementó `authGuard` para bloquear el acceso a rutas protegidas cuando no hay token.

Archivo:

- `sistema-comercial-app/src/app/guards/auth.guard.ts`

### 7. Eliminación del token hardcodeado

Antes, `CargoService` tenía un JWT pegado manualmente dentro del código.

Eso se retiró y ahora el servicio usa `HttpClient` normal, dejando que el token se agregue por el interceptor.

## Flujo final que quedó funcionando a nivel de código

1. El usuario entra a `/login`.
2. Ingresa `CorreoEmpresarial` y `Clave`.
3. El frontend llama a `POST /api/empleados/login`.
4. El backend devuelve el JWT.
5. El token se guarda en `localStorage`.
6. Angular navega a `/cargos`.
7. `CargoService` llama a `GET /api/cargos`.
8. El interceptor agrega el header `Authorization`.
9. Si no hay token, el guard redirige a `/login`.
